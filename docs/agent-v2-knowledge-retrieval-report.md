# AgentV2 K3/K4 关键词检索与引用实现记录

日期：2026-11-09。基线提交：949b8a2c8e5b02c9c6a59f067337257a40f8ac60；实现仍在当前工作区，未提交。状态：关键词纵向链路已编码，编译和定向静态检查通过，数据库与真实模型链路未验收。K3 混合检索尚未完成，K4 为首批实现，不能标记完整 RAG 完成。

## 已实现

- 迁移116为分块建立 PostgreSQL GIN 关键词索引，增加绑定 run/call 的检索记录与持久引用；不要求扩展权限，不安装 pgvector。已有完整解析分块在迁移时生成索引列。
- 排名模式固定为 `keyword-cjk-bigram-ascii-v1`：连续中文双字和完整小写 ASCII 标识符，按查询词覆盖率排序；最多召回40个候选、返回10个片段。分数不代表事实置信度，不是 BM25、语义检索或混合检索。单汉字与同义改写的召回有局限，尚无质量评估。
- 知识管理页面提供当前库关键词试搜；Agent 发送框提供知识范围选择。默认包含有权读取的全局知识与当前员工包知识，可额外选择应用知识库，每轮最多50个选择、冻结最多10000个文档版本。没有知识工具能力的员工不进入范围冻结流程；明确选择知识库时返回能力配置提示。
- 在发送事务中保存知识范围，Worker 任务快照保留范围和用户身份。每次检索/原文读取交集检查任务权限快照、当前用户权限、知识库归属与员工包版本；工具参数不能扩大范围。首次领取前员工能力沿用现有上下文准备合同，领取后不扩充已有工具快照。
- `knowledge_search` 返回片段、位置、版本、hash、引用ID及模式；`knowledge_read_document` 从同一 run 的引用按片段分页读取，最多10段，文本总量最多48KiB。分页从文档第0段开始，不能把检索命中当作完整文档。
- 检索记录按 run/call 与参数指纹去重，经当前执行权检查提交。重试恢复相同引用，重新过滤无权或已删除来源；保存前锁定来源，防止删除与引用创建竞争。检索记录额外只保留标识与排名，不复制正文；原有消息和工具结果仍按会话历史持久保存，删除知识不追溯改写已经生成的回答。
- 回答中的 `knowledge://citation/UUID` 仅在该消息真实工具结果包含该ID时转换为可打开引用。工具卡也提供来源按钮；来源面板重新授权并显示版本、位置、正文及鉴权原件下载。撤权、删除、卸载或许可证失效后拒绝再次读取。
- 文档更新后，已生成引用仍定位原冻结版本；新检索只使用当前完整解析版本。新版本解析失败保留之前完整解析版本。员工包知识另受当前安装知识版本约束，升级后不默认继续读取旧包。
- 所有知识文本作为不可信参考资料，不能变成系统规则、执行授权或确认依据；模型指导明确无证据不能编造引用。
- 运营中心能力目录新增两个明确能力，没有修改任何员工商品勾选、发布版本或本地安装包。

## 接口与合同

- `POST /api/knowledge/search`：知识管理试搜，按指定知识库授权，不创建Agent引用。
- `GET /api/knowledge/citations/{citation_id}`：仅引用所属用户访问，重新检查原会话、范围、员工与许可证。
- 发送请求新增可选 `knowledgeBaseIds`；缺省/空数组不改变原发送请求指纹序列化规则。
- API OpenAPI 与生成SDK已同步；Next知识BFF通用代理承接新接口。两个Agent工具走现有内部broker、checkpoint与持久工具事件，无第二套手写HTTP合同。
- 无知识范围快照的历史任务不自动获得新知识工具。工具合同变化可能要求已有活跃任务重新提交；不会自动重跑失败任务。旧会话的新一轮发送可生成新范围。

## 启用与手测

1. 正常重启配套开发服务：`./scripts/start-dev.ps1`。API启动使用平台现有增量迁移，需核实115/116执行成功；本轮没有代为应用迁移。运营中心也需按该项目现有方式重启API以加载新目录。
2. 在运营中心正常编辑员工能力，选择“检索知识库”和“读取知识来源”，保存发布后由客户平台更新安装。没有自动全选或扩大用户RBAC。
3. 在全局或应用知识库上传明确命名的测试文档，等待解析完成；先用试搜验证关键词命中、版本和定位。扫描PDF需OCR，当前不支持。
4. 新发一轮任务；应用资料需先在发送框知识范围中选择对应库。要求员工“查询资料并列出来源”，展开工具卡及回答引用，检查原文定位与下载。
5. 之后由用户手测刷新恢复、原文分页、文档更新、跨用户/员工/应用隔离、撤权/删除、重复调用与Worker恢复。不以代码存在代替这些验收证据。

## 剩余工作与限制

- K0/K3仍需专用Embedding/Reranker用途配置、供应商协议和凭据授权、pgvector可部署性验证、向量构建、RRF融合与重排。当前BYOM为聊天路由，不能直接拿聊天模型冒充Embedding；没有假设已有可用向量配置。
- 关键词SQL迁移、GIN执行计划、并发删除/撤权、幂等恢复和真实Rig引用链路尚未实测；无性能或质量通过结论。
- 独立工作台已提供显式应用范围选择；设计器内嵌对话本来尚未接入，本批没有实现自动从当前页面添加应用范围。
- 引用读取工具限定当前run；后续轮次需要重新检索生成本轮引用。分叉复制的纯历史文本若缺少原工具块，不把引用升级为新的可点击来源。
- 无语义检索、OCR、跨会话长期记忆、RAG质量标注集或生产容量验收。
- 撤权后来源面板下次请求拒绝访问；已经展示过的信息无法撤回用户已获知的内容，浏览器每5秒刷新授权结果，失败后不展示上次正文。
