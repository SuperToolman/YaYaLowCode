丫丫低代码平台系统架构

当前系统是一个同仓库、双运行时的模块化单体：Next.js 负责页面渲染、客户端交互和同源 BFF；Rust/Axum 负责安全边界、领域规则、Agent 执行与持久化。PostgreSQL 是唯一事实源，Valkey 只提供可降级缓存。

普通业务请求

  1. 页面调用领域 Hook。 UI 不直接拼接后端协议。
  2. 生成 SDK 请求同源 BFF。 React Query 管理缓存、取消和失效。
  3. BFF 转发认证。 Cookie 转为后端 Bearer Token。
  4. Axum 执行安全链。 RBAC 与许可证先于领域 Handler。
  5. 领域服务读写 PostgreSQL。 成功写入触发 Valkey 分类版本递增。

Agent 流式请求

  1. 会话绑定用户与页面上下文。 应用、业务和表单资源先校验归属。
  2. 运行时解析 Profile、Skill 与 Tool。 未授权工具不会注册为可调用能力。
  3. 模型产生工具调用。 每个工具再次执行 RBAC 和数据范围检查。
  4. SSE 返回增量事件。 前端批量合并 token，并展示资源名称与工具状态。
  5. 写操作进入确认链。 审计记录、Pending Action 和最终结果都持久化。

数据所有权

数据事实源恢复策略
应用、表单、记录、流程PostgreSQL必须备份
Agent 会话与审计PostgreSQL随业务库恢复
附件、Skill、许可证配置api-state与数据库成对备份
响应缓存Valkey无需备份，可重建
前端 Query Cache浏览器内存无需恢复
当前最重要的架构约束： 后端新增接口需要同时完成 Axum 路由、带 ToSchema 的 DTO、OpenAPI endpoint、生成 SDK 和 Next.js BFF Route Handler。任何一层缺失都会形成“后端能力已存在，但浏览器同源请求不可达”的断点。
部署形态：开发环境为独立 Next.js、Axum、PostgreSQL、可选 Valkey；单容器交付由 Supervisor 管理 Web、API 与 Valkey，入口脚本初始化本地 PostgreSQL，持久化数据位于 PostgreSQL 数据目录与 /var/lib/yaya。
