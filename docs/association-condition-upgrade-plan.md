# 公共条件组件与多层关联筛选升级计划

- 编写日期：2026-11-16
- 状态：核心功能已实施，完成自动化测试；页面人工验收与大数据性能基线待确认
- 适用项目：yaya-low-code
- 目标场景：数据表单视图筛选、集成自动化条件节点及公共条件组件的其他使用方

## 1. 背景与目标

当前关联表单字段保存的是目标记录 ID。记录表格会将 ID 解析成主显示字段，但视图筛选将输入文本直接传给后端。因此，用公司名称筛选保存了公司记录 ID 的“归属公司”字段无法正确命中。

本次不能只把文本框换成关联记录选择器，还需要支持按关联记录内部字段筛选，以及继续沿关联字段访问下一张表单。例如：

```text
客户管理 → 归属公司 → 联系人 = 小明
客户管理 → 归属公司 → 所属集团 → 负责人 = 小明
```

同时完善按字段类型配置条件的能力：选择数字字段时，仅提供适用运算符，并使用 HeroUI NumberField；日期、选项、成员等字段使用对应值选择器。

目标：

1. 视图筛选复用公共条件编辑器，不再维护独立条件控件。
2. 按最终字段类型决定运算符、值控件、序列化方式和校验规则。
3. 支持直接比较关联记录及沿多层关联选择终点字段。
4. 统一前后端条件语义，兼顾数据库查询和自动化上下文判断。
5. 兼容已有视图、自动化及其他条件配置。

## 3. 范围与边界

### 3.1 本次范围

- 公共条件协议、规则规范化、校验及序列化。
- 字段类型与运算符、值控件的统一能力定义。
- 单记录关联字段的多跳路径选择与执行。
- 视图筛选的公共组件接入和数据库过滤。
- 自动化条件、并行条件及使用条件的数据节点适配。
- 自定义按钮、关联默认值等已有使用方的协议和执行适配。
- OpenAPI、生成客户端、配置导入导出及兼容迁移。

### 3.2 需要独立定义的扩展

当前关联字段运行时为单选。本次多跳关联先以每一步指向单条记录为基础。

穿过子表、多选关联或反向一对多关系时，必须另外定义“任意满足”“全部满足”和多个条件是否由同一条子记录满足。不得将这些集合场景默认为普通单值路径，也不得让界面开放执行端尚不支持的路径。

本次不以修改关联字段存储为前提，不将公司名称替换为关系 ID，也不改变现有字段值的业务含义。

## 4. 总体设计

```text
宿主：视图 / 自动化 / 按钮 / 默认值
              ↓ 提供根数据来源和场景能力
         公共条件编辑器
              ↓
         版本化条件协议
              ↓
     服务端路径解析、类型和访问校验
              ↓
          可执行条件计划
           ↙          ↘
    参数化 SQL 编译    上下文条件执行
    数据库过滤分页    批量加载关联后判断
```

统一的是条件表达、比较语义和路径解析规则。数据库查询与节点输出判断使用不同执行方式，不强制全部转成同一种查询。

## 5. 字段类型、运算符和值控件

### 5.1 建立集中维护的能力定义

新增公共条件字段能力层，集中描述：

- 字段类型对应的语义值类型。
- 合法运算符及默认运算符。
- 单值、多值、区间或无需值。
- 对应值编辑器。
- 值转换、格式和精度校验。
- 字段间比较兼容性。
- 空值及集合判断语义。

字段描述需要携带字段 ID、名称、类型、数字精度、选项、是否多选、关联目标等信息。整数约束应读取实际数字字段配置；不能假设全部 number 都是整数。

前端和后端使用一致的能力规范及测试样例。后端依据可信 Schema 校验，不能仅接受前端声明的类型。

### 5.2 目标能力矩阵

以下为目标能力，具体字段类型需在实施前映射到项目实际组件及存储定义。

| 字段类别 | 适用运算符 | 值控件 |
| --- | --- | --- |
| 单行/多行文本 | 等于、不等于、包含、不包含、有值、无值 | Input / TextArea |
| 整数/小数 | 等于、不等于、大于、大于等于、小于、小于等于、区间、有值、无值 | HeroUI NumberField；区间使用两个输入 |
| 日期/日期时间 | 等于、不等于、早于、晚于、区间、有值、无值 | 与字段精度一致的日期/日期时间选择器 |
| 单选/下拉 | 等于、不等于、属于任意一个、不属于任意一个、有值、无值 | 单选或多选选项选择器 |
| 多选 | 包含任意、包含全部、不包含、有值、无值 | 多选选项选择器 |
| 布尔 | 是、否及实际字段允许的空值操作 | 布尔选择器 |
| 成员/部门 | 按单选或多选提供相应运算符 | 成员/部门选择器 |
| 关联字段本身 | 等于、不等于、属于任意一个、有值、无值 | 关联记录选择器 |
| 附件等复杂值 | 首先支持有值、无值 | 无需值控件 |
| 展示/执行类字段 | 不支持 | 不进入候选字段 |

不得把多选值的“包含”与文本子串匹配混为同一语义。

### 5.3 编辑状态处理

1. 切换字段时，保留兼容运算符，否则重置默认运算符。
2. 检查旧值是否兼容；不兼容时清空并提示重新填写。
3. 有值/无值无需值，执行时不读取残留值。
4. 多值使用数组保存，不使用逗号分隔作为新协议。
5. 区间包含两个端点，并明确是否包含边界。
6. 数字 0、布尔 false 都是合法值，不能按真假判断为空。
7. 数字范围等表单填写限制是否也限制筛选阈值，需要独立判断。例如允许填写 0～100 的字段，筛选“大于 200”本身仍是合法查询。
8. 右侧使用字段引用时，限制类型兼容性；关联字段还需校验目标表单一致性。

## 6. 多层关联字段选择

### 6.1 交互

公共组件提供逐层展开的路径选择：

```text
归属公司
  ├─ 使用此关联字段
  ├─ 公司名称
  ├─ 联系人
  └─ 所属集团
       ├─ 使用此关联字段
       ├─ 集团名称
       └─ 负责人
```

- “使用此关联字段”：比较记录 ID，显示记录名称。
- 选择目标表单普通字段：按该字段类型展示条件控件。
- 选择下一层关联：继续展开，支持 A → B → C → …。
- 已选路径显示完整名称，保存稳定字段 ID。
- 支持返回上层、修改路径及显示失效原因。

关联记录选择器应使用分页搜索接口，不能只加载前 100 条，也不应为了选择记录下载全部目标数据。

### 6.2 Schema 加载与限制

- 按需加载下一层字段结构，不递归预加载所有关联表单。
- 按表单和 Schema 版本缓存并去重请求。
- 左右字段引用共用路径选择能力。
- 配置最大跳数、条件数量和分组深度；具体数值经测试确定，可先以最多 8 跳评估。
- 允许有限自关联路径；重复出现同一表单不等于无限递归。
- 不支持或无权访问的字段不可作为可执行路径。

## 7. 统一条件协议

### 7.1 推荐结构

采用带版本的条件组/条件项结构。示意如下，名称和属性可在实现设计中调整：

```json
{
  "version": 2,
  "condition": {
    "kind": "group",
    "logic": "and",
    "children": [
      {
        "kind": "predicate",
        "left": {
          "source": { "kind": "currentRecord" },
          "relationPath": ["company_field_id", "group_field_id"],
          "fieldId": "contact_field_id"
        },
        "operator": "eq",
        "right": { "kind": "literal", "value": "小明" }
      }
    ]
  }
}
```

- relationPath 保存每一步的关联字段 ID，不保存展示名称。
- 中间目标表单由服务端根据 Schema 推导；前端元数据不作为可信依据。
- 当前表单直接字段使用空路径。
- 关联字段本身作为终点时，fieldId 即该关联字段 ID。
- 自动化来源使用 nodeOutput 与 nodeId，不再只用拼接字符串表达来源。
- 右侧字段引用使用与左侧一致的结构。
- 条件项和条件组保留稳定 ID，便于编辑、定位错误和迁移。

前端可以保留现有扁平编辑状态，但转换为统一协议时必须保持现有分组语义。

### 7.2 类型化值

| 值类别 | 新协议中的表示 |
| --- | --- |
| 文本 | string |
| 常规数字 | number，并与字段精度能力校验 |
| 高精度数值 | 如字段实际支持超出 JS 安全精度的值，采用显式十进制值协议，避免精度丢失 |
| 布尔 | boolean |
| 多值 | array |
| 日期/时间 | 约定格式字符串，明确时区/精度 |
| 区间 | 显式上下界和边界规则 |
| 关联记录 | 记录 ID 或 ID 数组 |

类型化条件值的落地不能破坏已有字符串条件的行为，迁移时按 Schema 转换并报告无法转换的项。

## 8. 后端路径解析与校验

增加公共条件解析层，职责包括：

1. 解析根数据来源和对应 Schema。
2. 检查每一步字段存在且确实为关联字段。
3. 从字段配置读取目标表单，再解析下一步。
4. 验证终点字段、运算符、值及字段间兼容性。
5. 检查各层表单、字段及记录访问范围。
6. 取得可信存储计划，形成可执行条件计划。
7. 限制规则规模并提供包含具体条件及路径位置的错误。

保存配置/发布时校验，执行时检查路径和访问范围是否仍有效。字段删除、关联目标改变等情况应报告失效，不能丢弃条件后扩大结果集。

当前条件、运算符的规范化入口需要同步升级。未识别运算符不得自动降级为等于。

## 9. 数据表单视图筛选

### 9.1 前端接入

- FormTableSetting 使用公共条件组件，删除重复条件行实现。
- 当前表单作为根来源，保留现有应用/取消和视图保存交互。
- 将统一条件传给记录查询接口。
- 筛选变化时回到第一页。
- 无效条件不能通过过滤空值等方式被静默跳过。
- 明细表单如仍使用不支持条件的接口，应明确接入其存储映射或限制入口，不能继续让界面配置后被忽略。

### 9.2 SQL 编译

推荐使用服务端解析后的参数化 SQL：

- 普通字段编译为类型化比较。
- 关联路径优先编译为嵌套 EXISTS。
- AND/OR 条件组编译为带明确括号的表达式。
- 表名、列名来自可信 FormStoragePlan，并验证标识符。
- 字段值使用绑定参数。
- SQL 与内存执行使用一致的空值和比较语义。

示意 SQL（非实际物理表名/列名）：

```sql
SELECT a.*
FROM customer_data AS a
WHERE a.deleted_at IS NULL
  AND EXISTS (
    SELECT 1
    FROM company_data AS b
    WHERE b.record_uuid = a.company_record_id
      AND b.deleted_at IS NULL
      AND EXISTS (
        SELECT 1
        FROM group_data AS c
        WHERE c.record_uuid = b.group_record_id
          AND c.deleted_at IS NULL
          AND c.contact_name = $1
      )
  )
ORDER BY a.created_at DESC, a.record_uuid
LIMIT $2 OFFSET $3;
```

实际路径是确定长度的，不需要递归 CTE。查询编译器按存储计划选择真实列或 JSON 表达式，避免不必要地重建整行 JSON 后再提取已物化的列。

数据和 COUNT 查询复用同一份条件计划及访问范围。EXISTS 用于保持根表记录粒度，避免关联造成重复行和总数失真。

## 10. 自动化条件及数据节点

### 10.1 适配入口

- 普通条件节点。
- 并行条件节点。
- 获取单条/多条数据。
- 使用规则筛选的更新、删除等节点。
- 保存、发布、执行、重试及运行恢复相关校验入口。

### 10.2 执行方式

数据库来源在语义允许时将条件下推到 SQL；触发数据和节点输出先批量解析关联，再进行类型化判断。

批量解析流程：

1. 保留上游节点输出作为根数据。
2. 收集第一层关联 ID，去重后批量加载。
3. 从已加载记录收集下一层 ID，继续批量解析。
4. 节点内共享关联缓存，完成全部规则判断。

不得为每条客户、每个条件分别执行关联查询。关联读取需要检查 schema/访问范围，缺失与读取错误不能混淆。

### 10.3 暂存变更和一致性

关联加载必须使用自动化运行上下文，读取本次运行暂存的新增、修改、删除，保留现有可见性规则。后续节点判断前序节点修改的联系人时，需要看到运行内的更新。

根节点输出不应被直接重新查库替换。关联数据使用运行可见状态；同一次节点判断尽量使用一致读取视图。实现中明确缓存生命周期，不能让前序更新后的缓存污染后续节点判断。

现有分支选择是同步比较逻辑。引入数据库关联读取后，需要调整引擎调用链，采用异步解析后判断，或先异步准备完整关联上下文，再执行纯判断；同时覆盖并行条件和恢复执行。

## 11. 必须统一的语义

| 问题 | 推荐处理 |
| --- | --- |
| 关联为空/目标删除 | 按路径无值处理；已删除数据不参与关联匹配 |
| 无权访问目标 | 返回访问错误，不伪装成无值 |
| 不等于与无值 | 明确是否包含无值；若沿用现有公共判断，SQL 也须覆盖缺失整条关联路径的情况 |
| 有值/无值 | 明确 null、空文本、空数组；数字 0 和 false 是有值 |
| 数字 | 按数值比较，遵守精度协议，不按字符串排序 |
| 日期/时间 | 明确时区、粒度及日级等于的时间范围 |
| 文本 | 明确大小写规则；包含操作中的 %、_ 等字符按约定作为字面文本处理 |
| 多值 | 使用真实数组及明确集合操作，不使用文本包含替代 |
| 多条节点输出 | 保留已有行为并显式定义任意/全部；同一记录满足多项还是不同记录分别满足需区分 |
| Schema 版本变化 | 视图按当前可用结构解析；自动化发布/运行版本应保留依赖信息，失效需明确报错 |

这些语义需在阶段一固定为规范和测试样例，不能留给各执行器自行解释。

## 12. 其他公共使用方

| 使用方 | 调整要求 |
| --- | --- |
| 自定义按钮配置 | 支持新字段类型、路径及协议；服务端执行校验同步升级 |
| 按钮可用性显示 | 对关联条件提供服务端批量判断或结果，避免浏览器逐行请求 |
| 关联默认值 | 接入服务端条件查询/解析，不能继续只对直接字段本地求值 |
| 表单设计器条件校验 | 支持路径终点和新运算符，正确展示失效提示 |
| 配置序列化 | 更新 normalize、API 转换及保存入口，不丢弃新增属性 |
| 应用导入导出/复制 | 按源表单上下文逐层重映射路径字段 ID，检查目标资源及版本变化 |
| OpenAPI 与客户端 | 更新 DTO、接口文档和生成类型，避免手工修改生成文件 |

公共组件由宿主提供根来源、可用能力、Schema 加载和记录搜索接口。所有使用方至少需要兼容新协议；执行端未接入的能力应限制配置入口，不能出现可配置但无法执行的状态。

## 13. 兼容迁移

1. 旧视图 filters 转换为 AND 组，保留 contains、equals、greaterThan 等原有操作。
2. 旧自动化 nodeId:fieldId 拆成来源与直接字段引用。
3. 旧 parentId 分组转换需精确保留逻辑，不可只按视觉层级重建。
4. 旧 rawValue 按字段和运算符进行适配；多值历史文本保留兼容读取路径。
5. 已保存的公司名称不自动猜成关联 ID；同名或无法解析项提示人工确认。
6. 未编辑配置支持兼容读取，保存时写新版本；持久化批量迁移如需进行，应独立设计并验证。
7. 覆盖历史流程版本、运行快照及重试恢复，不只验证最新编辑器保存。

### 17.1 已接入范围

- 视图筛选改为 `BranchRulesEditor`，旧 filters 在编辑时转换，保存 `conditionVersion: 2` 和 `conditionRules`。保留原 AND/OR、父子条件语义。
- 公共组件支持逐层进入关联表单，加载终点字段类型；数字使用 HeroUI NumberField，日期使用 DatePicker，时间使用时间输入，选项/成员/部门使用选择器，关联使用分页搜索记录选择器。切换字段和运算符会清理旧值。

- OpenAPI 和生成客户端已更新。应用包现有协议保留资源内部字段 ID 和节点 ID，因此条件路径保持原值；表单 ID 仍在关联组件配置中按现有机制映射，并添加回归测试。不存在需要改写路径内表单 ID 的新增属性。

### 17.2 实际协议

为兼容现有字符串回调和已保存的 `BranchRule`，没有将所有调用方一次性替换为新的 AST。保留 `fieldKey/rawValue/parentId`，使用带版本前缀的结构化封装：

```text
fieldKey = __condition_path_v2__:{"root":"company","path":["group","contact"]}
自动化 root = trigger-1:company
rawValue = __condition_value_v2__:100
rawValue = __condition_value_v2__:[2,10]
```

直接字段仍使用原 ID，旧字符串值继续读取。新值保留数字、布尔和一维数组；拒绝对象、多维数组、空匹配项和无效范围。已保存的名称不会猜测转换为记录 ID，需要重新选择记录。

### 17.3 SQL 与运行上下文

SQL 由后端根据 Schema 和存储计划编译。每跳通过目标表 `record_uuid` 的相关标量子查询取得终点值，外层完成比较；没有直接把前端字符串拼接进 SQL。表/列来自服务端受校验的物理存储映射，字段键和值使用绑定参数。

本次采用相关标量子查询，因为当前关联每步只指向一条记录；断链自然得到 NULL，便于统一不等于、不包含、无值以及左右字段比较的语义。外层不会因关联扩展产生重复记录，列表和 COUNT 使用相同谓词。并非前文候选方案中的逐层 EXISTS；未来多选关联需另行定义 any/all/none。

自动化使用同一服务端路径计划批量装载关联记录，不逐条逐层访问数据库。仓储按运行 ID 覆盖暂存新增、修改和删除，路径结果作为临时属性参与判断，不写入业务字段。负向比较包含断链记录；数字 0、布尔 false 均视为有值。

当前限制：最多 8 跳、200 条规则，批量判断每次 200 条，记录装载分批 500 个 ID。区间与任意值集合采用固定值输入；字段与字段比较要求类型兼容、关联目标一致，单选/多选设置一致。跨子表行和多选关联不在本次范围。
