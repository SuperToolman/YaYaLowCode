# AgentV2 知识库 K2：持久解析与分块

日期：2026-11-09。状态：代码已实现，编译与定向静态检查通过；未应用本机业务库迁移，未做数据库、浏览器、真实文档或模型验收。本批不是 RAG 检索交付。

## 本批范围

按专项架构 K2/C02 接在已有 K1 管理功能之后，实现「上传或员工包同步 → 持久任务 → 独立 Office helper → 结构化文本 → 分块事务提交 → 页面状态与预览」。三类知识库共享同一后台任务，不占用会话 FIFO。K3 Embedding/中文关键词/向量/RRF/重排，以及 K4 Agent 工具、范围快照与引用仍未实现，不注册空工具。

后台任务暂运行于 API 内的独立 Tokio 消费循环，复用现有独立 Office 子进程；没有增加必需服务。以后可将相同任务处理器部署为独立知识 Worker。任务只读本部署知识原件，正文不发送外部模型，不接触 Skill 执行环境。

## 持久化与恢复

- 增量迁移 `m20261109_000115_knowledge_parsing`：`knowledge_index_generations`、`knowledge_jobs`、`knowledge_chunks`，以及文档 `parsed_version_id`。不修改迁移114，不自动安装扩展或扩大数据库角色权限。
- 上传与员工包同步在现有事务内插入 generation/job；唯一键是版本、解析器、分块器。数据库任务本身就是本地解析的事务投递记录，本批没有外部索引消费者，未增加重复 outbox。
- 迁移将已有文档当前版本加入队列；历史原件及正式业务资料不删除。安装的历史员工包文档与当前包不一致时不激活；安装/许可证暂不可用时每60秒等待，不消费实际解析重试次数。旧包的处理结果不作为新包可用知识。
- 单进程一个消费者，使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 原子领取；多 API 实例可竞争。执行令牌 epoch、2分钟到期时间；helper 有20秒墙钟和10秒 CPU/512MiB 进程限制。解析期间不持有数据库事务。中断后到期可重领，不重用过期执行者结果。
- generation 显示 queued/processing/ready/failed/cancelled。job 另有 retry_wait/completed。解析器暂不可用/繁忙最多3次，间隔30秒；损坏、扫描件、超限直接失败，由管理者显式重试。重复重试不会重置进行中任务。
- 原件 SHA-256 校验后交给 helper。完整提取、分块及目标版本检查通过后，一次事务写入所有分块、激活该版本的解析 generation、更新 parsed_version_id。任务与结果状态同事务保存。失败不发布部分结果、不覆盖上一成功解析指针。
- 崩溃后从持久任务重做尚未提交的纯解析；本批没有逐页中间 checkpoint，也不会留下半份已激活分块。旧版本更新竞争时旧任务被取消，不能改变新版本的解析指针。原件删除级联清除任务、generation、分块；晚到结果不能重建文档。
- 服务退出时停止领取，取消 helper future；已领取任务靠到期恢复。没有依赖浏览器连接维持解析。

## 格式与覆盖边界

- TXT/Markdown：UTF-8 正文、原始行号，Markdown 最近标题。
- XLSX/ODS：一次打开工作簿，遍历所有工作表、行及列；按最多64列组织行单元，保留类型、缓存值、公式和坐标，每段附带第一物理行作为表头上下文，不推断多行语义表头。
- CSV/TSV：一次遍历，原始行列定位及首行上下文。不自动识别非UTF-8编码。
- DOCX：正文段落及表格单元格坐标；PPTX：按幻灯片顺序提取文字；文字 PDF：按页提取文本。
- 完整性限定为 `supported_text_layer` 全遍历，不代表完整视觉/版式或嵌入资源。DOCX页眉页脚、脚注、绘图、嵌入对象、PPTX图表及备注等不在提取范围；不执行宏、公式或脚本。PDF任意页面无文本则保守失败为需要OCR，空白页也可能需要人工调整；不激活混合扫描文档的部分文本。
- 原件仍为8MiB上限；提取文字及定位总量4MiB、最多20000个结构单元、最终4096分块。一般文本按结构单元内UTF-8边界最多2400字节切分，保留字节位置；不宣称使用精确tokenizer或已通过最优块大小评测。表格行保持整体，单行最多12KiB，超限失败而非截断单元格。PDF最多1000页，工作表最多100个、每表最多200万单元格；CSV最多10万行/1024列。达到限制整个 generation 失败。
- helper 最大结果8MiB，父进程输出上限12MiB。旧 helper 不识别新操作时显示需升级诊断。
- 尚未完成真实格式样本验收，不能将上述实现范围当作已通过 KR04 的证据。

## API 与页面

- `GET /api/knowledge/versions/{version_id}/parsing?offset=0`：重新校验文档权限与员工许可证/安装版本，每页最多20个分块。返回 coverage、状态、错误码、分块数及定位；不返回磁盘路径。
- `POST /api/knowledge/versions/{version_id}/reprocess`：复用已有知识管理权限，仅重试当前失败版本；员工包知识继续只读，不向客户端开放管理操作。
- KnowledgeDocument 增加 parsingError/chunkCount；status ready 在页面明确显示「已解析」，绝不是「可检索」。
- 管理页和员工详情显示持久状态；有待处理文档时每3秒刷新。查看解析结果使用分页模态框，正文按纯文本显示，禁止渲染资料HTML。管理者可在失败详情中重试。
- OpenAPI 与生成 SDK 已同步；复用现有 Next knowledge 通配代理，二进制上传/下载链不变。未手写 HTTP 请求合同。

## 启动与手测

在项目根目录运行 `./scripts/start-dev.ps1`，配套构建并使用新 API 与 Office helper；API 启动按平台既有迁移器应用115并启动解析消费循环。确保 `YAYA_AGENT_V2_OFFICE_PATH` 指向本次构建程序，启动脚本已有此传递逻辑。本次未重启正在运行的用户服务。

1. 全局/应用库上传明确命名的测试 TXT、Markdown、Excel、DOCX、PDF，确认「等待解析→解析中→已解析」，点击查看分块并翻页核对工作表/页/行列。
2. 失败文件应显示原因；修复运行环境后点重试。大文档/扫描PDF应明确拒绝，不显示已完成。
3. 更新文件时保留历史版本；并发更新、删除时旧任务不得激活新版本或复活删除资料。
4. 员工更新安装后，仅在当前员工详情看到本包资料与解析状态，无写管理按钮。
5. 重启解析中服务，等待执行权到期后应继续处理；跨用户/应用/员工读取仍执行现有权限。

回退先停止知识消费者/API，再回退代码，保留迁移、原件及解析数据；不自动执行 down 或删除资料。旧 API 无此消费者，队列会保留。K3还需要冻结并验证中文索引、pgvector部署、Embedding与Reranker用途配置；K4再接入Agent工具、范围快照和引用。未完成这些步骤前，上传资料仍不会被Agent检索回答。
