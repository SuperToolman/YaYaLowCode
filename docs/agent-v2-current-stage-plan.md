## 2. 当前必须遵循的规则

1. Agent 使用独立 Rust 执行链、Rig 和真实 Cordis，不恢复或依赖旧 DSH。市场兼容按实际包版本逐项验证，不宣称全市场兼容。
2. 员工能力描述员工会什么；实际资源操作由用户当前 RBAC 与任务权限快照共同约束。V2 不使用员工 applicationIds 作为授权层，不自动扩大正式员工能力或用户权限。
3. 保留员工使用权、安装、许可证、会话归属校验；会话和资源按部署、用户、员工隔离。
4. 平台业务工具的创建、编辑、删除必须确认；读取无需确认。未知通用写包装器不开放。
5. 脚本以当前系统账户本地执行，不要求 Docker 或 Skill 锁文件；员工安装、更新不运行 pip/npm。Agent 可根据真实缺包错误独立安装后重跑。
6. 会话目录、Python venv 和 Node 依赖持久保存；它们不是操作系统沙箱。Shell 无法强制保证平台业务工具的 RBAC、写确认和事务语义。
7. 不设置累计运行预算、模型请求配额或阶段步数上限，不恢复“增加预算并继续”交互。保留单次调用超时、停止、错误处理及未知执行结果核对。
8. 上下文管理服务于模型窗口适配；压缩只改变模型输入视图，不删除界面历史，不改变权限或已提交结果。
9. 供应商保留思考开关、参数协议和默认强度；不恢复“仅思考”“允许关闭思考”“支持档位”配置。强度选项由系统协议适配提供，具体模型兼容性需实际确认。
10. 前端使用 V2 自有组件、HeroUI、MySurface 和 Gravity UI，不引入旧 Agent feature 或 CSS Module。错误走全局通知，发送状态使用按钮和加载动画，不增加发送框状态文字。
11. 按当前用户偏好，不主动执行耗时回归或浏览器测试；采用必要的编译、类型及静态检查，页面由用户手动验收。未执行的验证明确登记，不视为通过。
12. 不恢复旧内容、不建立旧内容备份、不擅自删除客户业务数据。后续产品彻底删除必须由明确的用户操作触发。

## 4. 后续开发顺序

### 阶段 A：当前基线收敛

目标：让后续开发有一致、可启动、可手动复核的基线，不继续扩展供应商配置复杂度。

- A01：核对 API、Worker、manager、Office helper、Cordis、Web 的版本、配置和启动退出链路；构建避免覆盖运行中的二进制。
- A02：核对最新迁移与 SDK，特别是思考字段清理迁移 110；登记实际应用状态，不以导出 OpenAPI 代表数据库升级成功。
- A03：修正主文档中 Docker 强制、锁文件、48 步、累计预算、旧 Agent 保留等失效的“当前状态”；保留必要历史证据。
- A04：为用户手测维护精简操作清单：文本、图片、Excel、脚本缺包安装重跑、下载、停止、刷新恢复、T23/T31 确认。
- A05：真实故障按具体 run/session、错误类型和影响范围修复；不得将供应商 503、缺包和平台故障混为 execution_failed。

完成条件：启动方法、迁移状态、手测结果和已知问题明确；不要求在此阶段重新执行全部回归。

### 阶段 B：会话生命周期（下一开发优先项）

目标：补齐日常会话管理，并将工作区和运行任务纳入同一生命周期。

| 顺序 | 开发项 | 主要约束与完成条件 |
| --- | --- | --- |
| B01 | 标题修改、置顶和列表分页 | 明确排序及游标；不局限于首批会话；所有入口校验用户和员工归属 |
| B02 | 会话标题和消息全文搜索 | 服务端搜索、稳定分页、中文查询；按用户/员工、时间和归档状态过滤；不能只搜浏览器已加载列表 |
| B03 | 归档和恢复 | 归档不等于删除；恢复不重放历史任务；明确活跃任务下是否允许归档并冻结合同 |
| B04 | 彻底删除 | 持久删除任务及进度；停止/阻止任务继续写入，处理确认、事件、附件、产物、解析缓存和本地执行目录；晚到结果不得复活会话 |
| B05 | 会话分叉 | 明确消息边界、权限快照和附件引用；不复制已执行业务效果或重用 effect_key；分叉不自动执行旧工具 |

实施要求：API DTO、OpenAPI、SDK、BFF 和前端同步；确需持久字段时追加迁移，不改历史迁移。搜索、归档、删除均不得越过会话隔离。删除必须显示处理中、失败和完成，不能把请求受理当成数据已清除。文件共享引用若存在，先处理引用再回收。

手动验收重点：跨用户/员工不可操作；归档恢复前后消息和文件一致；大量会话可完整分页；删除与执行/上传竞争结果确定；删除失败可以查询和重试。

### 阶段 C：知识库 RAG 与检索

前置：会话归属与删除合同明确。现有业务查询和 Office 文件采样不视为 RAG。

1. C01：应用知识库、全局知识库、员工自带知识库，统一文档、版本和 ACL；全局不等于全员可见，不新增个人知识库。具体合同与 K0—K5 实施批次见[专项设计](agent-v2-knowledge-rag-architecture.md)。
2. C02：持久解析、分块、Embedding 和索引任务；重复提交幂等，失败版本不替换可用版本，模型维度变更隔离。
3. C03：中文关键词、向量及混合检索；根据实际 PostgreSQL/扩展环境确定方案，不把 pgvector 写成已部署事实。
4. C04：返回有界证据、来源段落/页码和版本；引用跳转重新鉴权，检索文本按不可信用户数据处理。
5. C05：权限撤销、文档更新/删除传播到索引、缓存及引用；禁止先召回越权内容再由前端隐藏。
6. C06：建立固定中文业务样本，记录召回、引用准确性、拒答与延迟；未评测前不承诺质量指标。

完成条件：从文档上传到引用回答形成真实链路，权限与删除传播可复核。长期记忆另设范围，不将 RAG 自动变为跨会话记忆。

### 阶段 D：平台工具闭环与办公交付

- D01：按 T 表补充实际服务、权限、确认、版本冲突、异常及恢复证据，优先 T23/T31 的真实设计修改。
- D02：T07 表单草稿回填：绑定页面、用户、员工、会话和草稿版本；过期或页面不匹配拒绝，不暗中保存记录。
- D03：T33 先盘点具体业务动作，再按明确工具接入；T32 通用写包装器继续默认拒绝。
- D04：真实 BOM Skill 完成“读取文件→缺包→安装→重跑→检查→产物下载”；保留原失败记录，不用空模板或退出码 0 代替业务交付。
- D05：补齐办公格式和错误提示；OCR、保真模板编辑等作为明确新批次，不混入基础解析修复。

完成条件：每个开放能力有准确状态和使用边界；只对已实际验证的工具更新验收结论。

### 阶段 E：Cordis 市场生态

- E01：选择实际必须支持的插件及版本，建立独立兼容清单。
- E02：实现来源/包身份/内容校验、安装与原子激活，失败保留当前可用版本。
- E03：完成配置注入、受控服务、加载、卸载、取消、崩溃和升级生命周期；不向 Host 注入用户 JWT、模型密钥或数据库连接串。
- E04：验证权限映射与结果合同；DSH 包兼容不得转为依赖 DSH 服务。

完成条件：至少选定的真实目标包完成安装、调用、更新及失败恢复；诊断样本不能替代市场兼容证据。

### 阶段 F：高级 Agent 能力（逐项确定需求）

候选顺序：持久 plan/todo/ask-user → 后台任务 → MCP/联网工具 → 调度 → 子 Agent → 更通用工作流。浏览器、LSP、代码辅助等按实际产品需求单独确认，不为复刻旧工具而一次性开放。

所有能力都要明确身份、权限继承、停止传播、持久恢复和结果归属。不存在累计运行预算不代表子任务可以无限递归；并发、递归深度和资源保护需作为独立技术合同讨论，不能擅自恢复已取消的用户预算交互。

### 阶段 G：发布质量与部署验收

- G01：Windows/Linux 实际执行、进程树停止、中文路径、依赖保持及输出收集。
- G02：明确命名的独立空库完整迁移、重复启动、升级及兼容回退；不能以随机 schema 代替全新实例通过。
- G03：真实模型、长脚本和隔夜运行；短时模拟不等于隔夜实测。
- G04：容量、并发、积压、日志、可观测性及告警；记录环境和负载，不空报性能。
- G05：发布包和启动脚本不依赖旧 DSH，不挂 Docker socket 启动旧任务容器；Linux 应用容器部署与本地执行合同一致。
- G06：明确系统账户执行的部署边界及供应链风险，不标记为强隔离沙箱。

该阶段是发布前必须补充的证据，并不表示现在自动执行耗时测试。未实测项继续作为发布缺口。
