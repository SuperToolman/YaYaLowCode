# 员工能力、用户 RBAC 与员工包同步实施报告

日期：2026-10-29。状态：代码与分层回归已完成，正式员工包发布到真实 T31 模型链路仍待验收。本文不代表整个 P4 或 AgentV2 完成。

## 权限规则

- 运营中心的员工能力决定模型可用工具，能力使用明确映射；读取能力不授予写入，通用包装器不授予全部写操作。
- 用户当前 RBAC 与任务启动时 RBAC 快照取交集，控制应用、表单、动作、行、字段和设计读写。员工使用权、有效许可证、安装检查、私有会话与写操作确认继续保留。
- V2 不读取员工 `applicationIds` 进行授权，不把空数组转换成通配权限。该字段留在旧合同和旧运行时中；运营中心编辑保留历史值，不新增应用范围页面。
- 策略版本升至 2。缺失或旧版权限快照的任务要求重新提交，不直接以新规则恢复。运行中新增用户权限不加入快照；员工内容变更要求新任务，权限收紧在执行和确认入口再次检查。
- T23/T31 仍要求完整字段读取、设计查看与编辑权限，仍检查基准版本/hash，保存与业务效果去重沿用既有事务。

## 改动位置与同步流程

| 位置 | 改动 |
| --- | --- |
| 运营中心 `api/src/main.rs` | 增加“修改表单设计”能力 `yaya_apply_design_patch`，说明强制确认 |
| 运营中心 `EmployeeModal.tsx` | 统一“员工能力”表述，保留历史 applicationIds；全选只选当前目录 |
| V2 core/tools、API broker、Worker | 能力别名对齐目录，移除员工应用限制，保留用户资源授权和策略版本校验 |
| 平台 settings、agent_config、config | 校验许可证/包身份/版本/内容，先下载解压校验后发布；普通失败保留原安装版本 |
| Web settings / V2 runtime | 更新安装成功后刷新员工列表与能力；市场显示安装/最新版本和失败原因 |
| Worker 工具结果 | 已提交写入向模型明确返回用户已批准且事务已完成，避免模型把执行结果误认为缺少确认 |

沿用“编辑保存员工能力 → 商品版本更新 → 客户市场发现更新 → 更新安装 → 新任务加载能力”的接口。未直接编辑本地安装包、未自动修改正式商品勾选结果。已有会话后续新任务使用当前安装内容；已启动任务不扩充内容快照。

安装将所有 Skill 下载到暂存目录，解压到平台自有不可变内容目录 `runtime/state/employee-skills/<hash>`；不依赖旧 DSH 目录。安装/卸载串行化，数据库资源在事务内更新，安装清单使用文件替换，普通提交错误恢复原清单与首次安装状态。

边界：安装清单文件与数据库不是跨系统原子事务。进程在文件发布与数据库提交之间崩溃仍存在不一致窗口，尚无持久安装日志/崩溃协调器；本批不声称已完成崩溃原子安装。包元数据来自带许可证认证的运营中心接口，并非独立包签名验证。失败暂存或未引用的内容目录不进入运行态，后续需增加保留/清理策略。
