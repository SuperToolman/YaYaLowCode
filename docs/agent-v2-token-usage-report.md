# AgentV2 会话 Token 用量

更新日期：2026-11-05。

## 展示调整

按后续用户要求，统计展示已移到每条 Agent 消息气泡内、运行状态／时间右侧。每条回复按其 run 汇总输入、输出和合计，包含该任务内的工具续答与摘要请求；发送框附近不再展示会话总量。历史接口为每个 run 返回独立用量，运行中和刷新后通过持久数据更新，避免把整个会话的消耗分配给每条回复。

## 已实现

- `/agent-v2` 在 Agent 消息气泡的状态／时间右侧显示该条回复所属任务的输入、输出与合计 Token，不受历史消息分页影响。
- Worker 将供应商实际返回的用量保存为 `model.usage` 持久事件，包含普通生成、工具续答及历史摘要请求。刷新和切换会话后从数据库重新汇总，SSE 事件触发更新。
- 兼容历史成功步骤的响应快照，并避免与新事件重复计数。不修改历史数据，不增加数据库迁移。
- 无用量记录时显示“暂无供应商用量记录”；已知存在未报告请求时显示“记录不完整”。不根据文本长度伪造消耗。
- 此功能只统计消耗，不增加 Token 配额、运行预算、暂停或执行限制，也不计算费用。重复发送的上下文每次按供应商实际输入用量计入；推理用量不额外叠加到输出总量。

## 数据存储

正式会话、消息、run、step、工具调用、确认及事件使用平台 PostgreSQL 持久存储；正式上传文件和生成文件的内容及元数据也通过数据库工作区保存。访问继续受部署、用户、员工及会话归属检查约束。

脚本执行的本地工作目录、Python venv、Node 依赖和 Skill 执行副本保存在服务器本地的会话目录中，不是数据库聊天记录。它们的正常目录分离不构成系统级安全沙箱。

## 统计边界

供应商未返回用量、流中断、Worker 在用量持久化前退出，均可能产生无法统计的真实消耗。旧失败请求与旧摘要请求也可能没有可恢复的用量，因此本统计不能替代供应商账单。全零的 SDK 默认用量不视为供应商确认的零消耗。

## 验证与启用

- API 编译及 OpenAPI 导出通过：`cargo run --locked --manifest-path api/Cargo.toml --target-dir agent-v2/target/validation -- --export-openapi`。
- Worker 编译检查通过：`cargo check --locked -p yaya-agent-v2-worker --manifest-path agent-v2/Cargo.toml --target-dir agent-v2/target/validation`。
- 在 `web` 执行 `pnpm run codegen:api` 成功，生成合同包含会话用量 DTO。
- 按用户要求，未运行回归测试或浏览器测试；真实供应商用量与页面展示待手动验证。
- 重启 API、Worker 和 Web 后生效，可使用项目开发入口 `./scripts/start-dev.ps1`。本次编译使用独立 validation target，未覆盖运行中的默认二进制。

## AI 员工管理接入（2026-11-06）

- `/settings/ai-employees` 员工列表显示会话累计 Token；会话详情弹窗增加输入、输出、合计和记录状态，并显示员工汇总。
- 范围为当前账号可访问的未归档会话；读取所有目录分页，避免原先只统计前 50 个会话。
- 目录接口新增可选 `include_token_usage`，在权限过滤与分页后批量汇总，不读取聊天正文。默认目录请求不增加用量查询。
- 与消息历史接口共享用量来源 SQL，继续使用供应商事件、旧成功步骤快照兼容和去重规则。无记录显示缺失状态，部分缺失显示“记录不完整”。
- 验证：隔离 PostgreSQL schema 测试通过，覆盖跨会话隔离、超过历史分页的累计、摘要请求、旧快照兼容与去重、缺失记录及空会话；前端统计测试 4 项通过，相关 ESLint 与 HTTP 边界检查通过。
- 全项目验证仍受已有错误影响：API 知识库模块 `KnowledgeDocument` 缺少反序列化实现及 `query_one` 调用类型错误；前端 `MyTable.test.tsx` 的 children 类型不匹配。样式边界检查还报告了消息页面已有的 CSS 命名及全局选择器问题。本次同步了用量相关 OpenAPI 字段并重新生成 SDK，完整 API 导出需待知识库编译恢复后运行；未进行浏览器验证。
