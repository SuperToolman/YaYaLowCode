# 知识库模型配置与检索链路

日期：2026-11-09

新建知识库仅需名称、描述、嵌入模型、可选重排序模型。模型选项来自已启用供应商的支持模型及已发布的知识服务连接。统一 SettingsContentCard 不变，不使用 CSS Modules。

## 实现

- 创建请求携带 description 和 retrieval，在后端调用嵌入接口验证并自动识别维度；知识库、连接发布及独立 profile 在同一个事务内保存。相同请求重试返回原知识库，修改内容后复用请求 ID 会拒绝。
- 新迁移 m20261109_000120_base_knowledge_retrieval 保存按库配置，保留旧平台配置作为既有知识库的回退。独立 profile 不会覆盖其他知识库的模型。
- 上传后由既有解析任务提取文本、分块；向量任务按知识库对应 profile 写入索引。
- 试搜及 AI 员工 knowledge_search 读取相应配置；任务提交时冻结各库 profile。跨模型查询分组检索和重排，再按倒数排名合并，不直接比较不同模型分数。
- 知识库显示嵌入/重排序模型、索引就绪/构建中/失败数，管理者可重试失败索引。移除独立知识检索入口。

## 验证

- 前端 TypeScript、相关文件 ESLint、HTTP 边界检查通过。
- Rust knowledge 测试：2 passed，0 failed，0 ignored。PostgreSQL 测试仅创建、操作并删除随机隔离 schema；模型服务使用本地 HTTP 模拟接口，无真实供应商调用。
- 覆盖建库描述与模型保存、创建防重复、3/4 维不同模型、上传 TXT、真实 office helper 解析、向量后台任务、按库试搜、可选重排、跨库结果合并、管理权限、文档版本和删除级联。
- AI 员工路径已接入相同检索方法及 profile 快照；本次未启动真实 AI 员工对话或真实云模型验收。

## 使用条件与现有限制

后端重启应用新迁移后使用。先在模型提供商中启用嵌入/重排序供应商并填写支持模型。嵌入接口需兼容 /embeddings，重排序接口需兼容 /rerank。首次索引异步构建，未就绪或供应商异常时按既有策略明确降级并在结果限制中说明。

现有向量维度为 1—4096，单 profile 检索范围最多 20000 分块，采用 PostgreSQL 数组精确余弦检索；不含 OCR。真实供应商密钥、接口兼容性及云服务网络尚未现场验证。
