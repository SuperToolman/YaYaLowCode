# AgentV2 客户平台统一知识检索调整

日期：2026-11-09。状态：代码与定向静态检查完成，未应用业务库迁移，未运行数据库、浏览器、真实模型或回归测试。本报告覆盖之前关键词/混合检索报告中的“按用户配置、按用户构建向量、知识读取按RBAC过滤”规则。

## 当前业务规则

- 客户平台统一维护一套Embedding及可选Reranker配置，与运营中心无关。全局、应用和AI员工自带知识使用同一套配置和向量构建服务。
- 同一客户部署、同一配置profile及文档generation只有一份构建任务和向量，不再随使用者分别构建。
- 所有已登录且有效的平台用户均可读取、试搜、下载有效知识原件；当前不叠加应用显示、knowledge_view或agent使用权作为知识文档读取条件。
- 应用归属仍用来组织资料，发送框选择应用库仍是范围约束；独立工作台默认全局及当前员工自带知识。Agent不能借工具参数越过该任务冻结范围。
- 员工知识保持有效安装、许可证、当前知识包版本检查；Agent仍只使用当前执行员工的包内知识。员工知识管理仍在运营中心，客户端不能改写包内容。
- 使用Agent的员工使用权、能力目录、许可证及用户有效性保持原规则。共享的是知识资料和索引，不是他人的会话、附件、工具结果或私有引用；这些继续按用户/会话隔离。
- 知识管理/上传/删除及模型设置/重试仍使用原管理权限；此次放开的是读取，不是把所有平台用户改成管理员。业务记录查询与写工具的行字段RBAC、确认和事务不受影响。

## 实现

1. 新增迁移118，为vector profiles增加deployment_id，以部署为单位约束唯一活跃配置和配置指纹。profile上的user_id仅是配置操作人审计，不再用于运行授权；操作人被删除时置空，不级联删除共享索引。
2. 新增knowledge_provider_connections，在管理员显式保存检索配置时把所选BYOM连接的名称、地址及已加密密钥发布为平台知识服务连接。只在服务端保存密文，不向模型、浏览器、Worker或日志返回密钥。
3. 个人聊天路由继续由个人管理。平台连接独立运行，不依赖配置管理员登录、账号状态或个人路由存在。修改个人聊天连接不会默默修改已经发布的平台密钥；需要更新平台知识服务时在知识检索设置重新选择并保存连接。
4. 其他有模型管理权限的管理员可以复用已经发布的平台连接，设置返回的platformConnections仅含ID和名称，不含密钥。个人连接不能被普通检索用户任意传入执行器。
5. 向量任务的发现、领取和运行固定当前knowledge_deployment_scope。后台按批发现当前部署所有已解析且有效资料，每次发现最多100份，按每任务16分块构建；不再等待各用户分别试搜才安排索引。新文档解析完成后在后续轮询进入同一平台索引。
6. 知识读取统一允许有效登录用户；全局知识库设置入口、应用库选择、员工知识只读面板同步去掉旧读取权限门槛。原管理权限及员工包生命周期检查保留。
7. 新任务知识范围使用ruleVersion=2，冻结当前平台profile。旧ruleVersion=1任务不自动按新规则扩展，需重新发送任务；旧历史引用仍在原冻结版本和会话所有者约束内读取。
8. OpenAPI及SDK同步新增平台连接名称列表；HTTP接口路径保持不变，Next BFF沿用现有合同。

## 升级与启用

正常重启配套服务：`./scripts/start-dev.ps1`，核对平台迁移118执行成功。本轮没有重启现有服务或代为升级业务库。

迁移不会自行选择某个历史个人配置作为全平台配置。旧个人profile和向量保留但停用，不删除资料、文件、会话或原配置，也不创建旧内容备份。

管理员需在 `/settings/model-providers` → “知识检索”中保存一次平台配置。第一次保存可选择自己的已启用供应商，后续管理员也可选择已发布的平台连接。保存后后台为三类有效知识统一构建，设置页显示平台统一进度和失败原因。新任务使用该平台配置，旧任务保持原冻结合同。

## 待手测与保留限制

- 两个不同用户应获得同一profile，检索同一文档不产生第二套向量；无knowledge_view权限用户应可列表、试搜和下载，但不能上传/删除。
- 配置管理员退出、禁用或删除后，其他有效用户仍可使用已经发布的平台连接；密钥轮换需重新保存平台配置。
- 并发管理员保存、不同部署的profile/连接/文档隔离、构建重启、员工卸载/许可证失效、老任务和历史引用需实测。
- 迁移118及上述SQL没有在真实数据库执行；真实Embedding/Reranker链路与质量/容量仍未验证。
- PostgreSQL精确余弦、RRF、可选重排及明确降级规则保持；pgvector/HNSW和生产质量门槛仍未完成。

## 2026-11-09 硅基流动 Qwen3 接口核对

核对官方 https://api-docs.siliconflow.cn/docs/api/embeddings-post ：预设Base URL为https://api.siliconflow.cn/v1，实际调用/embeddings，Bearer Key、model、字符串数组input与encoding_format=float兼容。官方对Qwen/Qwen3-Embedding-8B列出的dimensions为64、128、256、512、768、1024、1536、2048、2560、4096；4B最高2560、0.6B最高1024，详见官方枚举。

修复原实现只检查输出维度却未传dimensions的问题：仅对官方api.siliconflow.cn及三个明确Qwen3-Embedding模型发送所选dimensions，保存时和请求时校验官方枚举；其他供应商/模型请求不变。设置页面增加8B维度提示。API独立target编译通过，日志knowledge-siliconflow-api-check.log。未使用客户Key做真实付费调用，未改变现有配置。

当前新增供应商仍为聊天路由表单，需要真实聊天模型；向量模型应在独立知识检索设置中填写，不能冒充默认聊天模型。不宣称纯Embedding供应商的独立新增表单已经实现。若已有硅基流动聊天连接，可以直接在知识检索中选它并配置Qwen/Qwen3-Embedding-8B。重启后新配置生效，维度变更会使用新profile重新构建，不混用历史向量。
